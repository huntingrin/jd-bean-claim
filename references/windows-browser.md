# Windows 浏览器接入

本说明适用于 Windows 上需要为本技能配置浏览器能力的 Agent。已有可用浏览器工具时直接复用，无需再安装 MCP。用户或宿主指定的浏览器规则优先；不修改系统默认浏览器，不自动启用被禁用的工具。

## 前提和选择

- 推荐 Windows 11、Node.js 24 LTS、已安装的 Edge 或 Chrome，以及支持本地 stdio MCP 的 Agent。Node.js 需在宿主进程的 PATH 中；安装后可能需要重启 Agent。
- 最新支持范围以 [Playwright 系统要求](https://playwright.dev/docs/intro#system-requirements) 为准。Windows 10 不列为本项目已验证环境；WSL 与 Windows 原生进程的路径和浏览器连接不同，不直接套用以下配置。
- 希望复用日常浏览器登录：选择扩展模式。希望单独保存京东登录：选择专用配置目录模式。两种模式只配置一种，同名 MCP 条目不要重复添加。
- 示例为常见的 `mcpServers` JSON 格式，宿主若使用 TOML、设置面板或其他格式，应按其文档转换 `command` 和 `args`，不要覆盖整个配置文件。`cmd.exe /d /c` 用于 Windows 下启动 npm 提供的 `npx` 命令。

安装 Skill 不会自动加载这些配置。`npx -y @playwright/mcp@latest` 首次运行需要联网下载软件；示例跟随上游版本，完成本机验证后可改用验证过的具体版本号。本仓库没有捆绑 MCP、浏览器或账号状态。

## 方式一：扩展连接现有 Edge／Chrome

1. 在目标浏览器的目标用户配置中，按 [微软官方扩展说明](https://github.com/microsoft/playwright/blob/main/packages/extension/README.md) 安装 Playwright 扩展。Edge 如提示来自其他商店的扩展安装许可，由用户自行处理。
2. 把 [扩展模式配置](../examples/windows-extension.mcp.json) 中的 MCP 条目合并到宿主配置，重新加载 MCP。此模式使用 `--extension`，不指定 `--user-data-dir`。
3. 用户在目标浏览器打开 <https://bean.jd.com/myJingBean/list> 并自行登录；首次连接时在扩展页面批准连接并选择任务页面。Agent 不代点浏览器拥有的授权提示。
4. Agent 读取所选页面，确认是本次任务使用的京东账户，再进行下面的只读验收。连接可能要求再次授权，不自动配置绕过授权的令牌。

扩展连接会复用该浏览器配置的登录状态，不需要导出 Cookie。多个浏览器或用户配置同时存在时，以用户实际授权的页面为准；无法确认连接到哪一个时先澄清。系统默认浏览器若不受支持，应由用户选择 Edge 或 Chrome，不能仅根据系统默认设置自动接管。

## 方式二：启动专用 Edge 配置目录

1. 使用 [独立 Edge 配置](../examples/windows-edge-profile.mcp.json)。把 `YOUR_WINDOWS_USER` 路径替换为本机实际的专用目录，推荐放在当前用户的本地应用数据目录中、仓库之外；JSON 中使用 `/` 或转义后的 `\\`。不要依赖宿主一定展开 `%LOCALAPPDATA%`。
2. 示例使用 `--browser msedge`。若选用已安装的 Chrome，改成 `--browser chrome`，并为它使用不同的专用目录。不要指向日常 Edge／Chrome 的 `User Data` 目录，也不要拷贝日常浏览器的 Cookie。
3. 重新加载 MCP，在它启动的浏览器中由用户首次登录京东。后续使用同一目录可保留登录，过期后仍需重新登录；同一目录不能同时被多个浏览器实例占用。
4. 默认保留有界面模式，便于登录和验证。确需无界面运行时，可在完成登录、关闭本任务实例后添加 `--headless`，再验证同一目录中的登录是否仍有效。无界面不保证京东可用；遇验证应交接用户，不重试绕过。

独立模式不使用扩展，也不继承日常浏览器的登录。浏览器配置目录和 MCP 输出可能包含账户资料，应保存在仓库之外；截图和对账记录按 SKILL.md 保存到用户任务目录。不要使用 `--isolated` 代替持久目录，否则关闭会话后登录状态不会按本方案保留。

不提供默认配置目录的调试端口接管方案。[Chrome 136 起限制默认目录的远程调试启动参数](https://developer.chrome.com/blog/remote-debugging-port)，本技能也不需要暴露调试端口。

## 只读验收与执行衔接

首次接入先给 Agent 这个请求：

> 使用 jd-bean-claim，仅检查浏览器连接、京豆余额、待领区域和签到状态，不点击领取或签到；如需登录或连接授权，保留当前页面交给我。

Agent 按实际工具接口完成：

1. 确认导航、页面读取、点击工具可用；在签到图片缺少明确文字时，还需要截图和图像理解能力。只检查工具能力，不以点击领取按钮测试连接。
2. 记录任务所属页面标识和所选连接方式。导航到京豆页面，确认当前实际 URL、账户以及余额和流水正常加载；登录页或空白页不算连接验收成功。
3. 通过页面快照读取状态；签到不明确时查看签到卡片截图，不按图片 URL 或连续天数推断当日状态。缺少视觉能力且页面没有明确状态时，保留“签到状态待核实”。
4. 可选使用 `scripts/collect-state.mjs`。它是浏览器页面函数：支持直接函数调用的适配器使用 `page.evaluate(collectBeanState)`；MCP 若只接受函数字符串，按当前工具 schema 传入完整函数源码。不要在页面函数内导入本地模块，也不要把 Ego 的 API 当作 Playwright API。
5. 报告余额、待领状态、签到状态及缺失信息。只有用户授权领取后，才回到 SKILL.md 的购物返豆／每日签到步骤；已有授权无需再询问。

## 后台运行、恢复和结束

- 常规操作使用页面级点击、填充和截图，不调用 `bringToFront`、`Target.activateTarget` 或系统鼠标键盘。扩展授权、窗口创建或登录可能影响前台，尚未证明 Windows 全流程不抢焦点；用户要求严格后台运行而当前工具无法满足时，说明具体限制并停在交接点。
- 用户接管页面时停止自动操作；登录、授权或验证码处理完并确认后，恢复同一任务页面。Ego 的 TaskSpace API 只适用于 Ego，不要求 Playwright 实现同名接口。
- 点击后断连或超时，先恢复原页面并对账；不得切换后端、换配置目录或重新创建会话后盲目重复领取。
- 完成后仅关闭本任务创建且用户无需保留的页面。连接日常浏览器时，不使用可能关闭整个浏览器的操作；只按工具文档断开任务连接。独立模式可以关闭本任务启动的实例，保留专用配置目录供下次登录使用。

## 常见问题和验证范围

| 现象 | 下一步 |
| --- | --- |
| 宿主找不到 `npx` 或 MCP 启动失败 | 在 Windows 终端检查 `node --version`、`npx --version`；确认宿主 PATH 和配置格式，不循环安装 |
| MCP 已启动但无法连接日常浏览器 | 确认扩展安装在目标用户配置，且使用 `--extension`；让用户完成连接授权 |
| 独立模式提示找不到浏览器 | 确认所选 Edge／Chrome 已安装，核对 `msedge`／`chrome`；不擅自改系统默认项 |
| 专用目录被占用 | 关闭本任务的旧实例后恢复，不终止用户其他浏览器进程 |
| 登录、验证码或 App 专属入口 | 交接用户或报告电脑端限制，不把无法执行写成已领取 |
